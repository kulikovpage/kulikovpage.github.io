# Сайт с проектами

Сайт-визитка, только на английском: главная со списком проектов, у каждого проекта своя страница (иконка, обложка, скриншоты, описание, связь) и политика конфиденциальности. Адрес пока https://kulikovpage.github.io, домен подключается позже.

- Главная: `/`
- Страница проекта: `/<имя>/` (App Store Connect → Support URL)
- Политика конфиденциальности: `/<имя>/privacy/` (App Store Connect → Privacy Policy URL)

## Как добавить проект (≈10–15 мин)

1. Открыть https://kulikovpage.github.io/admin/ и войти (см. ниже).
2. Projects → **New Project**.
3. Заполнить форму. Обязательно только название, остальное можно позже:
   - One-line description — одна фраза под названием;
   - Status: «Coming soon», «Beta» или «On the App Store» (с ним появится кнопка App Store);
   - иконка, цвет, платформы, обложка, скриншоты, описание;
   - Privacy policy — уже заполнена шаблоном для приложения без сбора данных: заменить APP NAME и EMAIL и проверить каждую строку.
4. **Save**. Через 1–2 минуты проект на сайте: карточка на главной, своя страница и политика.

Скрыть проект, не удаляя: галочка **Hide from the site**. Порядок на главной: поле **Position** (меньше — выше).

Тексты главной и почта: **Site settings → Home page and contacts**.

## Вход в админку (один раз на устройство, ≈5 мин)

Админка (Sveltia CMS) сохраняет изменения прямо в этот репозиторий на GitHub, своего сервера у неё нет. Для входа нужен ключ доступа GitHub:

1. На экране входа нажать **«Sign In with Token»** («Войти с помощью токена доступа»). Кнопку «Sign In with GitHub» не нажимать: для неё нужен отдельный сервер.
2. В окне будет ссылка на страницу создания ключа в GitHub с уже выбранными правами. Создать ключ: доступ только к репозиторию `kulikovpage.github.io`, права **Contents: Read and write**, срок — например, год.
3. Скопировать ключ и вставить в окно входа.

Ключ хранится только в этом браузере. Никому его не пересылать. Если он утёк — удалить его в GitHub → Settings → Developer settings → Personal access tokens и создать новый.

## Как это устроено

- `content/site.json` — тексты главной; `content/projects/*.json` — по файлу на проект.
- `public/` — копируется как есть: админка (`admin/`), загруженные картинки (`uploads/`), стили и скрипты (`assets/`). Картинки из админки сами уменьшаются и сохраняются в WebP.
- `build.py` собирает страницы в `dist/`. Только стандартный Python, ничего не устанавливает.
- `.github/workflows/deploy.yml` — после каждого сохранения GitHub сам собирает и публикует сайт.

Собрать у себя: `python3 build.py`, затем открыть `dist/` любым статическим сервером.

## Свой домен (когда купим)

1. GitHub → репозиторий → Settings → Pages → Custom domain: вписать домен.
2. У регистратора домена добавить записи DNS, которые покажет GitHub.
3. В админке: Site settings → Site address → новый адрес. В `public/admin/config.yml` поменять `site_url` и `display_url`.
4. Новые ссылки на политику и помощь вписать в App Store Connect.
